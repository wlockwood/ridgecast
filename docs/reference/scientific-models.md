# Optional scientific CPU models

Both capabilities below are explicitly enabled and preserve older network defaults. Required data and environmental assumptions are reported separately from the scientific model's validity. Terrain calculations run in workers, snapshot settings, and check cancellation between paths and around native calculations. Once required geographic data is locally available, the kernels perform no network I/O.

## Complete outdoor P.1812

**P.1812-7 outdoor (ITU troposcatter correction)** is a separate CPU model from **Terrain diffraction (P.1812-inspired)**. The existing inspired model keeps its saved identifier and behavior. The complete model identifier is `itu_r_p1812_7_outdoor`; its implementation revision is `itu-p1812-7-outdoor-crc-62e7b871-troposcatter6-v1`.

The backend is [CRC Canada's MIT-licensed implementation](https://github.com/ic-crc/crc-covlib/tree/62e7b871e28db6aaa93ab2e3864d9f89dd147a68), pinned commit `62e7b871e28db6aaa93ab2e3864d9f89dd147a68`. It implements P.1812-7 outdoor procedures, using [ITU's advised P.1812-6 troposcatter equation 44 correction](https://www.itu.int/rec/R-REC-P.1812-7-202308-S/en). It includes line of sight, delta-Bullington and spherical-earth diffraction, ducting/layer reflection, corrected troposcatter, mechanism combination, representative clutter and genuine time/location statistics. Optional indoor building-entry loss and the alternative attachment 3 spherical-earth approximation are outside the outdoor contract. It makes no indoor coverage claim.

Required inputs are bare-earth profile, physical antenna heights above bare earth, representative interior clutter heights, endpoint coordinates, explicit refractivity gradient DN and sea-level N0, and radio-climatic zones. Application-generated profiles use an explicitly chosen uniform sea/coastal-land/inland zone; sea and coast are not inferred from NLCD or elevation. The scientific API also accepts a mixed per-sample zone profile. Optional coast distances default to values derived from the explicit zone/distance profile. No restricted ITU digital maps are bundled or automatically downloaded. Missing environmental inputs or unknown required geographic data make predictions unavailable.

The supported application contract is 30–6000 MHz, physical antenna heights 1–3000 m, latitude ±80°, longitude ±180°, time percentage 1–50%, location percentage 1–99%, prediction resolution 1–1000 m, DN −100–156 N/km, N0 0–500 N-units and paths up to 3000 km. Profiles contain 3–20000 strictly ordered finite samples. These are input limits, not promises of accuracy throughout every environment. Time/location loss non-exceedance is distinct from radio-link availability or statistical confidence. This model uses CPU dispatch and bypasses optimistic free-space pruning.

The independent numerical gate uses [19 ITU Working Party 3K approved reference profiles](https://github.com/eeveetza/p1812/tree/6e2f00b662544a4320e6ba7c93e4f8b09c7a4c62), pinned revision `6e2f00b662544a4320e6ba7c93e4f8b09c7a4c62`, with 63 expected results. They cover rural/urban clutter, both polarizations, sea/coastal/land zones, short/long paths, line of sight/subpath diffraction and 1/10/50% time. Independent native validation passed all 63 with maximum loss error `4.48192452e-08 dB`; the Rust bridge repeats these cases. Source hashes, licenses and reproduction instructions are retained in `cpp/third_party/crc_p1812` and `tests/fixtures/p1812_complete`.

## P.372 atmospheric noise at 20–30 MHz

The optional atmospheric component uses [ITU-R-HF's P372 software 14.3](https://github.com/ITU-R-Study-Group-3/ITU-R-HF/tree/82017594a1c6cacfaa7e86954c4ae7b3a5825a3d), pinned commit `82017594a1c6cacfaa7e86954c4ae7b3a5825a3d`. Its revision is `itu-p372-software-14.3-82017594-atmospheric-v1`. The source notice permits implementing/revising the Recommendation free from copyright assertions; attribution and original data hashes accompany the embedded coefficient pack. The runtime independently verifies SHA-256 `2506c1abd5b49e0ef08ca19917479d72956007f790285f9fb1384878dca8d665` before using it.

Explicit preparation selects that verified bundled data, month 1–12 and UTC hour 0–23. The receiver's actual latitude/longitude is required. Outside 20–30 MHz, an unsupported range is reported rather than extrapolated. Monthly location and local mean-time interpolation follow the pinned source. Median external atmospheric power is `kT0B + Fam` and is summed in linear power with receiver and incidental man-made noise. A compatible measured floor keeps precedence and receives no extra atmospheric addition. Reports retain the atmospheric contribution, inputs, revision and unavailable reason independently of RF validity.

Coverage evaluates the assumed receiving radio at each downlink sample and the actual site receiver for uplink samples. Site Finder likewise uses each receiving point when atmospheric noise is enabled. These jobs capture their configuration and run on CPU; disabling the option preserves their previous receiver references. If a requested atmospheric component is unavailable, modeled coverage, facility and candidate sample margins remain unknown. A compatible measured total floor is still usable. Link/scenario APIs return a specific unavailable-noise error when a complete receiver reference cannot be established. Unknown samples are excluded from coverage claims, rather than replaced with zero atmospheric power.

The source's upper/lower decile curves clamp frequency to 20 MHz above that frequency. This feature adds atmospheric noise only; it does not add galactic noise, ionospheric propagation, or a complete expected HF floor. Existing propagation-model frequency limits still apply. All twelve monthly coefficient sets are embedded, so explicit preparation and evaluation need no download. Independent expected values come from the unmodified pinned ITU C implementation at different hemispheres, longitudes, seasons and UTC hours, with reproduction assets in `tests/fixtures/atmospheric`.

In the desktop Ambient Noise Settings window, **Prepare bundled P.372 atmospheric data** enables the component; choose month and UTC hour there. MCP uses `configure_atmospheric_noise` with `session_id`, `enabled`, `month` and `utc_hour`. Complete outdoor propagation uses the structured `change_settings.p1812_complete` object; see the [MCP reference](mcp-server.md) for its explicit environmental fields. Workers keep these captured settings even if later jobs use different settings; at most four MCP workers can run concurrently.

See [propagation settings](propagation-settings.md), [model limitations](model-limitations.md), [noise and fade margin](../concepts/link-budget-and-noise.md), and [co-channel scenarios](interference-scenarios.md).

Individual profiles, height trials, selected path overlays and coverage workers retain their captured ITM or complete P.1812 environment, including configured canopy calculations and result provenance. Complete P.1812 receives the actual geographic endpoints and representative clutter for each path or prefix; reverse predictions retain the reversed terminal and coast-distance inputs. Named interference scenarios and signal-at-point candidate diagnostics reuse cached LiDAR surfaces and remain cancellable. Use explicit individual profile preparation to acquire a missing surface.
